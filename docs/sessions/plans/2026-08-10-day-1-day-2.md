# Goal Plan — Day 1 and Day 2

## Goal

Achieve the cleanest possible verified completion of every Day 1 and Day 2
deliverable and Gate G1/G2 condition in `docs/09_ONE_WEEK_SPRINT_PLAN.md`.

This means:

1. implement all locally executable work in dependency order;
2. validate every completed result with executable or operational evidence;
3. use real non-production services wherever configuration is available;
4. preserve the complete documented scope;
5. record an item as `BLOCKED` when external evidence is impossible, never as
   complete or silently deferred.

## Mandatory repository instructions

Execution must follow [`AGENTS.md`](../../../AGENTS.md). It defines the personal
GitHub identity and remote, signed atomic commits, branch/pull-request policy,
BDD/TDD cycle, coding standards, test strategy, quality gates, and evidence
protocol.

No development starts until its pre-development approval checklist is accepted.

## Goal completion

The Goal is complete only when both gates pass.

### Gate G1

- Two Workspaces and Projects exist in non-production.
- Cross-Workspace CRUD, search, aggregate, file, notification, Realtime, and
  provider access is denied.
- Root, current slug, historical redirect, and unavailable routes pass in
  French and English.
- Preview contains no production or provider secret.
- Provider callbacks cannot cross Workspace or Project scope.
- The Appwrite 10 MB Function-ingress result is recorded.

### Gate G2

- Unidentified and externally identified Reporters submit and retrieve.
- Reference-only retrieval is denied without existence disclosure.
- JPEG, PNG, WebP, GIF, PDF, TXT, and CSV pass actual-content validation.
- Spoofed, polyglot, malware, archive, executable, oversized, binary-text, and
  sixth-file cases fail.
- Any file or commit failure returns no Feedback success and leaves no durable
  orphan.

## Completion rules for every task

A task can move to `DONE` only when:

- its implementation is reviewable and deployable;
- its positive, negative, isolation, retry, and failure paths pass;
- trusted Functions enforce scope for protected behavior;
- affected UI passes FR/EN, keyboard, accessible-name, non-color, and 320 px
  checks;
- logs, caches, responses, and built assets contain no prohibited data;
- install, typecheck, tests, and build pass;
- deployed evidence is attached when the task depends on Appwrite, Vercel, or a
  provider.

## Execution path

The stages are sequential. Within a stage, tests and evidence are part of the
implementation rather than a later cleanup activity.

### Stage 1 — delivery spine (`TASK-DEL-001`, `TASK-TEST-001`)

Create:

- `apps/web`, `packages/domain`, and `functions/api` workspaces;
- strict TypeScript and reproducible dependency lock;
- React/Vite PWA shell and Vercel SPA/cache policy;
- Vitest, Testing Library, API-contract, and Playwright harnesses;
- one positive and one fail-closed test in each active layer.

Validate:

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
```

Exit: all four commands pass from the repository root and the client bundle
contains no secret-like value.

### Stage 2 — environment and observability (`TASK-DEL-002`, `TASK-OBS-001`, `TASK-VER-001`)

Create:

- typed public/server environment contracts and environment-identity checks;
- startup rejection for missing, mixed, or secret-bearing public config;
- correlation IDs, structured redaction, metrics, traces, Web Vitals, and
  availability probes;
- deployed preview smoke for SPA fallback and cache headers.

Validate:

- configuration unit and contract tests;
- built-asset and log prohibited-data scans;
- preview-to-production cross-environment denial;
- deployed deep-link and cache-header smoke.

Exit: local implementation passes. Parent tasks remain `BLOCKED` until separate
Appwrite/Vercel environments and telemetry provide operational evidence.

### Stage 3 — isolation, roles, and routes (`TASK-OWN-001`, `TASK-AUTH-001`, `TASK-PROJ-001`)

Create:

- Workspace/Project ownership records and trusted scope derivation;
- Owner and assigned-Maintainer mapping with deny-by-default policy;
- two-Workspace/two-Project deterministic fixtures;
- global current/historical slug reservation and non-reassignment;
- root, current, history, inactive, reserved, and unavailable route behavior;
- FR/EN root with no Project/Workspace catalog operation.

Validate:

- complete protected-operation isolation matrix;
- Owner/assigned/unassigned/removed/forged role matrix;
- slug collision, history, redirect, direct-link, inactive-intake, and
  root-no-enumeration matrix;
- component and browser checks in FR/EN, by keyboard, and at 320 px.

Exit: local matrices pass, then the same matrices pass against non-production
Appwrite with two real Workspaces and Projects.

### Stage 4 — provider and upload foundations (`TASK-SRC-001`, `TASK-ATT-001`)

Create:

- provider-neutral source-connection ports;
- owner-only connect, callback state/nonce, encrypted grant, repository
  selection, suspend/disconnect, and revocation policy;
- GitHub and GitLab adapters behind those ports;
- reproducible 10 MB plus multipart/protocol-overhead ingress probe.

Validate:

- CSRF, replay, cross-scope, unselected-repository, secret-leak, and revocation
  tests;
- real non-production GitHub App and GitLab OAuth callback exercises;
- deployed Appwrite Function upload probe.

Exit: `TASK-SRC-001` and `TASK-ATT-001` are `DONE`, then Gate G1 passes.

### Stage 5 — Reporter and feedback contracts (`TASK-REP-001`, `TASK-FDB-001`)

Create:

- unidentified, contact, issuer-scoped external-ID, and trusted-assertion
  Reporter attribution with audit history;
- separate Bug, Suggestion, and Review source contracts;
- bounded declarative Context with source, purpose, and trust state;
- FR/EN type selection, form semantics, and intentional Context review.

Validate:

- cross-issuer/application/Workspace identities never merge;
- public identity stays unverified and no fingerprint is collected;
- required, optional, malformed, undeclared, executable, and size-boundary
  source/Context cases;
- source and Context remain separate from derived classification;
- FR/EN, keyboard, language-preservation, non-color, and 320 px checks.

Exit: `TASK-REP-001` and `TASK-FDB-001` are `DONE`.

### Stage 6 — accountless access and acceptance (`TASK-ACC-001`, `TASK-INTAKE-001`)

Create:

- stable human reference and independent high-entropy Feedback proof;
- one-way verifier, rotation/revocation, and Reporter-safe projection;
- `clientOperationId` idempotency and payload conflict detection;
- Appwrite transaction for Reporter, source, Context, `received` history,
  verifier, notification, and durable outbox;
- confirmation and proof-preservation experience.

Validate:

- reference-only, invalid, revoked, and sibling proof return indistinguishable
  denial;
- response-loss retry creates exactly one effect;
- changed-payload key reuse conflicts;
- forced transaction failure returns no success/reference/proof;
- notification failure preserves the accepted source fact;
- Reporter projection contains no Internal Note, internal classification,
  unrelated Feedback, or audit data.

Exit: `TASK-ACC-001` and `TASK-INTAKE-001` are `DONE`.

### Stage 7 — private Attachment saga (`TASK-ATT-002`, `TASK-ATT-003`)

Create:

- private request-owned staging and manifest limits;
- actual-content detection, parsing/decoding, strict UTF-8, malware port,
  digest, archive/executable/polyglot rejection;
- atomic metadata association after all files validate;
- failure cleanup, stale-stage sweeper, and reconciliation;
- scope/audience-authorized download and Feedback lifecycle binding.

Validate:

- seven accepted-format fixtures;
- spoofed, polyglot, malware, archive, executable, binary-text, oversized, and
  sixth-file fixtures;
- any-file and commit failures produce no Feedback success or durable orphan;
- Reporter/internal-evidence, sibling, removed-assignment, and cross-scope
  downloads fail;
- deletion immediately hides files.

Exit: `TASK-ATT-002` and `TASK-ATT-003` are `DONE`, then Gate G2 passes and the
Goal can be marked complete.
