# Goal Plan — Day 1 and Day 2

## Goal

Achieve the cleanest possible verified completion of every Day 1 and Day 2
deliverable and Gate G1/G2 condition in `docs/09_ONE_WEEK_SPRINT_PLAN.md`.

This means:

1. implement all locally executable work in dependency order;
2. validate every completed result with executable or operational evidence;
3. use real non-production services wherever configuration is available;
4. preserve the complete documented scope;
5. record an item as `BLOCKED` when external evidence is impossible, never as
   complete or silently deferred.

## Mandatory repository instructions

Execution must follow [`AGENTS.md`](../../../AGENTS.md). It defines the personal
GitHub identity and remote, human-attributed atomic commits without machine
co-authorship, branch/pull-request policy, BDD/TDD cycle, coding standards, test
strategy, quality gates, and evidence protocol.

No development starts until its pre-development approval checklist is accepted.

## Goal completion

The Goal is complete only when both gates pass.

### Gate G1

- Two Workspaces and Projects exist in non-production.
- Cross-Workspace CRUD, search, aggregate, file, notification, Realtime, and
  provider access is denied.
- Root, current slug, historical redirect, and unavailable routes pass in
  French and English.
- Preview contains no production or provider secret.
- Provider callbacks cannot cross Workspace or Project scope.
- The Appwrite 10 MB Function-ingress result is recorded.

### Gate G2

- Unidentified and externally identified Reporters submit and retrieve.
- Reference-only retrieval is denied without existence disclosure.
- JPEG, PNG, WebP, GIF, PDF, TXT, and CSV pass actual-content validation.
- Spoofed, polyglot, malware, archive, executable, oversized, binary-text, and
  sixth-file cases fail.
- Any file or commit failure returns no Feedback success and leaves no durable
  orphan.

## Completion rules for every task

A task can move to `DONE` only when:

- its implementation is reviewable and deployable;
- its positive, negative, isolation, retry, and failure paths pass;
- trusted Functions enforce scope for protected behavior;
- affected UI passes FR/EN, keyboard, accessible-name, non-color, and 320 px
  checks;
- logs, caches, responses, and built assets contain no prohibited data;
- install, typecheck, tests, and build pass;
- deployed evidence is attached when the task depends on Appwrite, Vercel, or a
  provider.
